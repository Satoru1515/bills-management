# Android app (Capacitor)

The Android app is a thin [Capacitor](https://capacitorjs.com/) shell around the deployed web app: its WebView opens the site's URL instead of bundled files, so the phone always runs the same code as the website and a new deployment updates the app without a new APK. The native project lives in [`android/`](../android) and is committed; build outputs are not.

| Setting                | Value                                   | Where                                        |
| ---------------------- | --------------------------------------- | -------------------------------------------- |
| App ID (package name)  | `com.satoru1515.bills`                  | `capacitor.config.ts`, `android/app/build.gradle` |
| App name               | Bills                                   | `capacitor.config.ts`, `android/app/src/main/res/values/strings.xml` |
| URL it opens           | `CAP_SERVER_URL` (or `NEXT_PUBLIC_APP_URL`) at sync time | `capacitor.config.ts`              |
| Android versions       | minSdk 24 (Android 7.0), target/compile SDK 36 | `android/variables.gradle`            |
| Icons and splash       | Generated by `npm run icons`            | `src/lib/pwa/icon-image.ts`                  |

> **The app ID cannot change once the app is published on Google Play.** To use another one, change `appId` in `capacitor.config.ts`, then `namespace` and `applicationId` in `android/app/build.gradle` and the package of `MainActivity.java` (and its folder) before the first release.

> **Google sign-in does not work inside the app yet.** Google blocks OAuth in embedded WebViews (`403 disallowed_useragent`). The next task of the plan opens the sign-in in the system browser and returns to the app through a deep link. Until then the app shows the login page but cannot finish signing in.

## Requirements

- Node.js 22 or newer (the Capacitor CLI needs it) and `npm install` done in the repo.
- [Android Studio](https://developer.android.com/studio), which brings the JDK (21) and the Android SDK. Open it once and let it install the SDK for API 36.
- For a phone: USB debugging turned on (Settings → About phone → tap _Build number_ 7 times → Developer options → USB debugging). Or an emulator from Android Studio's Device Manager.

## 1. Point the app at the deployed site

The URL is read from the environment when you run `cap sync` and written into `android/app/src/main/assets/capacitor.config.json` (git-ignored, so no URL is committed). It must be `https`; plain `http` is accepted only for `localhost`, `127.0.0.1` and `10.0.2.2` (development).

PowerShell:

```powershell
$env:CAP_SERVER_URL = "https://your-app.vercel.app"
npm run android:sync
```

Bash:

```bash
CAP_SERVER_URL=https://your-app.vercel.app npm run android:sync
```

If neither `CAP_SERVER_URL` nor `NEXT_PUBLIC_APP_URL` is set, the app shows a page saying the URL is missing (`mobile/www/index.html`). Run `npm run android:sync` again after changing the URL, `capacitor.config.ts`, or Capacitor plugins.

To try the app against your computer's dev server from the **emulator**, use `CAP_SERVER_URL=http://10.0.2.2:3000` (`10.0.2.2` is the host machine as seen from the emulator) and keep `npm run dev` running.

## 2. Build a debug APK

From Android Studio: `npm run android:open`, wait for Gradle to sync, then **Build → Build App Bundle(s) / APK(s) → Build APK(s)**.

From the command line (needs `JAVA_HOME` pointing at Android Studio's JDK, e.g. `C:\Program Files\Android\Android Studio\jbr`):

```bash
cd android
./gradlew assembleDebug
```

On Windows `cmd`/PowerShell use `.\gradlew.bat assembleDebug`. The APK is at `android/app/build/outputs/apk/debug/app-debug.apk`.

Install it on a connected phone or a running emulator:

```bash
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

Or press **Run** in Android Studio. A debug APK is signed with a local debug key; it is fine for your own phone but not for Google Play.

## 3. Build a signed release APK (optional)

1. Create a keystore once and keep it **outside the repo** with its passwords in a password manager (losing it means you cannot update the app on Google Play):

   ```bash
   keytool -genkeypair -v -keystore bills-release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias bills
   ```

2. In Android Studio: **Build → Generate Signed App Bundle or APK → APK**, choose the keystore, build variant `release`.
3. The APK is at `android/app/release/app-release.apk`.

`*.jks` and `*.keystore` are git-ignored; never commit them or their passwords.

## How it fits together

- `capacitor.config.ts` builds the config from the environment (`resolveServerUrl` validates the URL; tests in `src/test/capacitor-config.test.ts`).
- `server.cleartext` is only turned on for an `http` development URL, and `android.allowMixedContent` is off.
- The web app's service worker (`public/sw.js`) also runs inside the WebView, so the offline page shows when the phone has no connection.
- Launcher icons (`mipmap-*`: square, round and the adaptive-icon foreground on the `#2F5D8A` background) and launch screens (`drawable*/splash.png`) are drawn by `src/lib/pwa/icon-image.ts`; run `npm run icons` after changing the drawing.
